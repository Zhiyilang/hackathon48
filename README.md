# hackathon48 — 48 小时极限开发作战包

给线下黑客松用的一套东西：**一个生成即全绿的脚手架**，加**一份按小时排的作战手册**。

它针对 2026 苏客松（10-30 ~ 11-01，苏州独墅湖，总奖金 ¥50 万，免费餐食住宿）
写成，但适用于任何「48 小时内必须交付可运行作品」的场合。

---

## 一、先说清楚：黑客松输在哪

不是输在想法不够好。复盘多次后会发现，失败几乎总在这四类里：

| 失败模式 | 表现 | 代价 |
|---|---|---|
| **最后一小时在救环境** | 演示前才发现控制台编码崩、依赖装不上 | 有功能也没得演 |
| **宣称无法验证** | 说自己"做得很快"，但没有任何东西能复现 | 评委默认当吹牛处理 |
| **垂直切片太晚** | 先做漂亮的解析器，最后发现端到端没跑通 | 交付的是半成品 |
| **熬夜把第二天废掉** | 第 30 小时彻底失能，最后 18 小时零产出 | 相当于只踢了半场 |

这套包对付的正是这四条。

## 二、用法

```bash
python scaffold.py MyProject --author "你的名字"    # 生成并立即验证
python scaffold.py --selfcheck                       # 自检：生成+验证+敌意locale+幂等
```

生成物 9 个文件，**跑 `python eval.py` 立即全绿**（生成物的种子断言数量以
`--selfcheck` 实跑输出为准）。两者是两个不同的套件，数字不要混用。
这一点很重要：起点是绿的，之后你加的每一条断言才是真回归测试，
而不是「在救火途中顺手记一笔」。

## 三、五道内置防御（每条背后是一次真实事故）

| 防御 | 真实事故 |
|---|---|
| `money` | 银行家舍入把 `0.005` 变成 `0` —— **消失的半分钱正好是那个项目要防的事故本身** |
| `units` | `100 CNY` 被认作等于 `100 USD` |
| `alias` | 付款参考列被行 id 静默覆盖，最高质量匹配被降级且**无任何报错** |
| `stdout` | 演示途中控制台崩 UnicodeEncodeError |
| `evidence` | 没有理由的结论无法审计 |

这五条不是注释，是**可执行的种子断言**。你删得掉注释，删不掉断言。

## 四、48 小时时间表

### T+0 ~ T+2　选题与立项（**上限 2 小时**）

超过 2 小时还没定题，后面必崩。三条判据：

1. 能不能在 **8 小时内做出端到端最薄切片**？不能就换。
2. 有没有**一个真实的、具体的人**因此受益？评委对"泛用平台"无感。
3. 演示能不能**一次命令跑出画面**？跑不出来的别选。

> 苏客松特别提示：约 80% 赛题来自园区企业真实场景，采用
> 「企业出题、青年解题、产业阅卷、资本接力」。这意味着
> **评委席就是需求方**——选题时优先选能被现场企业代表认领的题目。

### T+2 ~ T+8　垂直切片 + 第一条断言

目标：一条命令，输入 → 输出，端到端走通。哪怕中间全是桩。

同时开始写 `eval.py`。**先写断言再写实现**的顺序在这里格外值钱：
它逼你在写之前先定义什么叫"对"。

### T+8 ~ T+20　核心逻辑，断言同步增长

纪律：**任何一处你在 README 里写下的宣称，必须同时有一条断言。**
这条纪律会在今天深夜救你——因为第二天你会困到分不清改了什么。

### T+20 ~ T+28　**去睡觉**

这是整份手册里最难执行、收益最高的一条。

48 小时不睡的人，第 30 小时后基本是负产出：写代码、删代码、
再写回来。留 8 小时缓冲给睡眠，你得到的是两个清醒的半天，
而不是一个半天的清醒加一个半天的幻觉。

走前必做：提交一版，**写下三行「回来看这里」的笔记**——
下一步做什么、现在绿不绿、卡在哪。睡眠后的大脑读不懂睡眠前的上下文。

### T+28 ~ T+38　收口：README + 演示视频 + 双语文档

- README 只需回答三件事：**它做什么 / 怎么跑 / 凭什么信你**
- 演示视频：真实命令的真实输出，**不要渲染动画**。镜头可以是静态截图
  加终端输出，但输出必须是真的
- 双语（中英）成本极低，覆盖面立刻翻倍

### T+38 ~ T+44　演练

**完整跑一遍 demo，用主办方的环境，而不是你的机器。**
这一遍一定会发现东西——这正是它的意义。

### T+44 ~ T+48　提交 + 缓冲

留 4 小时。提交系统总在最后一小时出问题，这不是玄学，是排队。

## 五、评委到底在看什么

以 PayPal AI Hackathon 2026 官方口径为例，**五维等权重**（唯一有明确公开 rubric 的参照）：

Technology / Design / Impact / Idea / Presentation

注意 **Presentation 占五分之一**，且它是唯一一项你在最后两小时还能大幅改善的。
另外，多数黑客松先做一道 **pass/fail 合规检查**（跑不跑得起来、用没用到指定技术）——
这一关不过，后面四项再好也不计分。所以：

> **能跑 > 说得清楚 > 功能多。**
> 顺序不能颠倒。

## 六、提交前硬性自检清单

```
[ ] 干净目录里重新 clone/解压，按 README 的步骤能跑起来
[ ] python eval.py 全绿（这条不绿，其它都免谈）
[ ] LC_ALL=C LANG=C 下 eval.py 全绿（主办方机器未必是 UTF-8）
[ ] demo 视频：真实终端输出，非渲染动画
[ ] README 里每个数字都能在 eval.py 找到对应断言
[ ] 没有 __pycache__ / .pyc / .git 混进提交包
[ ] 打包文件名符合主办方要求（很多赛事要求「项目名+队长姓名.zip」）
[ ] 提交后自己下载回来验证一次
```

最后一条最常被跳过，也最常出事：
**你上传的那个 zip，必须解压到一个干净目录再跑一遍。**

## 七、这套包自己的验证

```bash
python scaffold.py --selfcheck
```

自检四件事：生成成功 → `eval.py` 全绿 → 敌意 locale 下全绿 → 重复生成幂等。
零第三方依赖（仅标准库），Python 3.9+。

| 指标 | 实测 |
|---|---|
| 本包断言数（`python eval.py`） | 51 / 51 |
| 敌意 locale（`LC_ALL=C`）下 | 51 / 51 |
| 生成物断言数（`--selfcheck` 实跑输出） | ≥ 30 |

它自己也是一个「每条宣称都有断言」的样本：
`--selfcheck` 的输出就是它的全部证据。
